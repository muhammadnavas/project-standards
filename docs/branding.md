# Brand and UI Standards

These guidelines establish a consistent, usable interface. They do not prescribe one universal visual identity for every product.

## Brand foundations

Each project MUST document its product name, purpose, audience, personality, and approved logo/assets. Product-specific identity belongs in that project's own brand guide.

## Visual consistency

- Use a small, intentional color palette with named design tokens (for example: primary, surface, text, muted, success, warning, danger).
- Check text/background contrast; do not communicate status through color alone.
- Use a consistent type scale, font weights, spacing scale, radii, shadows, and icon style.
- Prefer design tokens over scattered hard-coded values.
- Use a consistent grid and responsive breakpoints.
- Use real product assets and approved logos. Do not stretch, recolor, or distort brand marks.
- Avoid gratuitous gradients, shadows, animation, and decorative elements that reduce clarity.

## Components and interaction

- Reuse shared components for repeated patterns.
- Provide visible hover, focus, active, disabled, loading, success, and error states where relevant.
- Use semantic controls: buttons for actions, links for navigation, and form elements for input.
- Destructive actions require clear labeling and appropriate confirmation or undo.
- Forms must have labels, useful validation messages, and clear error recovery.
- Keep layouts responsive across supported screen sizes.

## Accessibility

- Aim for WCAG 2.2 AA where practical and applicable.
- Support keyboard navigation and visible focus.
- Provide accessible names for controls and meaningful alternative text for informative images.
- Respect reduced-motion preferences.
- Use semantic headings and landmarks; maintain logical reading order.
- Do not rely on placeholder text as the only form label.

## Content

Use concise, plain language. Keep terminology consistent. Explain empty states, errors, and next steps. Avoid fake testimonials, fabricated metrics, and misleading interface copy.

## Project-specific brand guide

Each project SHOULD define its own logo usage, exact color tokens, typography, component library, imagery, tone of voice, and examples of correct/incorrect usage.
